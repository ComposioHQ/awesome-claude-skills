# 检索渠道策略（source playbook）

检索开始前必读。含四通道策略、网络环境适配、联系方式获取规则。

## 四通道策略

### 1. 学术通道

候选人在论文、课题组页面留下的痕迹最真实、最容易核实学历。

- **导师实验室页面**：`cs.<校>.edu/~<导师>/` 的学生名单 + 毕业去向是黄金来源，一次能挖出一组人
- **顶级会议论文**：NeurIPS / ICML / ICLR / ACL / CVPR / AAAI 目标方向论文的华人一作与核心作者；再沿引用链找同方向研究者
- **博士论文**：标题页含导师、委员会、毕业年份、现任单位
- **综述文章**：目标方向的 survey 引用列表是现成的候选人池
- **竞赛**：Kaggle GM、阿里云天池、NOI/ACM 金牌选手（量化岗尤其有效，注意核查后续职业路径）
- 入口：Google Scholar / Semantic Scholar API / 会议 proceedings。可搜论文标题，可抓 arXiv API（export.arxiv.org/api/query）

### 2. GitHub 通道

- 目标方向知名开源项目的 contributors 与 core maintainers（LLM 方向如 vLLM、SGLang、DeepSeek、Qwen、LLaMA 系、Triton；量化方向如 LightGBM、XGBoost、各类 backtest 框架）
- 论文官方实现 repo 的作者（作者身份与学术通道互相印证）
- 公司开源组织（github.com/<org>）成员列表
- GitHub profile 常直接带邮箱、个人主页、现职 → **联系方式首选来源**

### 3. 公司通道

- 目标公司 research/AI 团队页面（OpenAI、Anthropic、Meta、Google、xAI、DeepSeek、字节、阿里、腾讯、MiniMax、月之暗面等；量化：幻方、九坤、明汯、灵均、衍复等）
- 公司技术博客作者署名、公司开源组织成员
- 用户给的 JD 里提到的团队/负责人 → 反向找其团队成员与同门

### 4. 社区/职业平台通道（华人候选线索主通道）

- **知乎**：方向话题高赞答主、团队招聘贴答主、面试经验贴提到的人
- **公众号/掘金/CSDN**：技术文章作者简介常带学历与现职
- **LinkedIn 公开页**：搜「学校 + 方向关键词 + 公司」组合
- **脉脉 / 猎聘 / Boss直聘**：职业档案核实现职与任职时间（需登录态的站点用浏览器自动化工具；职业平台的档案可能滞后，最终以公司官网一手来源为准）
- 即刻/小红书 AI 从业者（反爬强，用浏览器自动化工具）
- 播客/讲座（TechBeat、将门、AI Time）嘉宾名单

## 联系方式获取规则

只收集**公开**信息，按优先级：

1. GitHub profile 邮箱与主页链接
2. 个人主页 contact 页邮箱
3. 论文通讯作者邮箱（公开出版信息）
4. LinkedIn 公开页（不买会员、不自动加好友）

禁止：买数据、爬付费数据库、进封闭群组、用抓取工具批量爬联系方式。

## 地域约束（可选参数）

用户设定了地域约束时（如「只找目前在国内工作的候选人」），在获取与核实信息时特别核实现职工作地点：

- GitHub profile：检查用户是否在个人信息中标注所在城市/国家（如 "Beijing, China"）
- 个人主页：查看「关于我」或联系方式页是否包含要求地域内的地址
- 论文通讯作者：通讯地址若包含要求地域内的高校/科研院所则符合
- LinkedIn 公开页：当前职位所在地是否在要求地域内
- 其他渠道：任何公开信息中出现的现职工作地点

若现职工作地点明确不符合约束（且用户未要求包括海外），该候选人应被剔除并在检索记录中注明「作废（地域不符）」。用户未设定地域约束时不做此筛选。

## 网络环境适配

- **内置检索工具**：优先用宿主 Agent 内置的网络检索/抓取工具，走内置通道通常无需代理。搜论文标题/人名/公司，抓取 API（arXiv、Semantic Scholar、OpenAlex、GitHub API）和网页内容。
- **浏览器自动化**：需登录态的站点（脉脉、LinkedIn、即刻、小红书）用本机可用的浏览器自动化 skill/工具操作浏览器，并确保账号合规登录。
- **代理**（备选）：如直连特定站点超时，按本机网络环境自行配置 `https_proxy`。多数 `.edu.cn` 站点直连反而通、走代理反而断；外网站点视网络环境决定是否走代理。

## 子代理分治约定

- 各通道相互独立 → 如宿主支持，用子代理机制并行派发；每个子代理 prompt 必须包含工具指令（「使用宿主的网络检索工具检索公开信息，如需浏览器操作则加载本机可用的浏览器自动化 skill」）
- prompt 用目标导向写法（「获取」「调研」「了解」），不写暗示具体手段的词
- 子代理只回传卡片列表，不写文件；主代理负责去重、核实、成表
- 检索记录中记录实际使用的工具与命中情况，方便下次复盘

## 检索记录格式约定

格式模板内嵌于 `SKILL.md` 第 3 步：

- 标题：`# 检索记录：<主题>（对标 <基准人>）`
- `## 任务要求`：画像摘要 + 全部约束（含中途追加的约束，标注追加时间；地域约束；验证方法：单轮验证为必需，五遍验证为可选深度验证）
- `## 检索过程`：表格 `时间 | 查询/操作 | 结果与决策`；不达标的候选人写「作废（原因）」
- `## 网络环境注意事项`：本次新发现的网络坑
- `## 待办`：未完事项
